## 🚀 TENTANG AUTO & RINGKASAN PROYEK

**AUTO (Alinlabs Utility Technology Operations)** adalah aplikasi web utilitas rekayasa perangkat lunak generasi mutakhir yang diciptakan untuk menyederhanakan, mengamankan, dan mengotomasi seluruh alur kerja version control Git, pengiriman skrip otomasi payload, sinkronisasi file berukuran besar (*Git Large File Storage*), rilis repositori GitHub, serta manajemen dokumentasi proyek.

Platform ini hadir sebagai solusi terintegrasi (*all-in-one developer companion*) bagi software engineer, sysadmin, DevOps engineer, maupun tim pengembang untuk menghilangkan repetisi perintah manual Git, mencegah kegagalan pipeline CI/CD, mengeliminasi kesalahan fatal human error pada sinkronisasi branch, dan mengoptimalkan build cloud di platform modern seperti **Vercel**.

* **Aplikasi Web Resmi:** [https://auto-alinlabs.vercel.app](https://auto-alinlabs.vercel.app)
* **Kategori Perangkat Lunak:** Developer Tools, DevOps Automation, Version Control Utilities.
* **Lisensi:** MIT Open Source License.

## 🎯 LATAR BELAKANG & MASALAH YANG DIPECAHKAN

Proses deployment kode dari lingkungan lokal ke GitHub dan hosting cloud (Vercel, Cloudflare Pages, Netlify) seringkali mengalami kendala teknis yang berulang:

1. **Vercel Git LFS Build Failure (130-Byte Pointer Error):**
   Ketika file binary (video MP4, ZIP, PSD, model 3D, executable) dilacak menggunakan Git LFS, GitHub hanya menyimpan *pointer metadata* berukuran ~130 byte pada repositori Git standar. Secara default, build server Vercel tidak mengunduh konten file asli LFS jika variabel `VERCEL_GIT_LFS_ENABLED=1` tidak disetel, menyebabkan file rusak saat aplikasi berjalan.
   * **Solusi AUTO:** Memberikan peringatan solutif, tombol satu klik untuk menyalin variabel lingkungan, serta menghasilkan skrip push Git LFS otomatis.

2. **File README.md Terselip di Folder `public/`:**
   Banyak pengembang meletakkan file README dokumentasi di dalam folder `public/` (misalnya saat mengekspor proyek framework modern). Akibatnya, repositori GitHub tidak menampilkan README di halaman utama root repositori.
   * **Solusi AUTO:** Fitur **Readme Detector** otomatis mendeteksi keberadaan file README di `public/` dan memindahkannya ke root sebelum proses push.

3. **Windows PowerShell ExecutionPolicy Lock:**
   Windows secara default memblokir eksekusi skrip `.ps1` dari pihak ketiga (*Restricted Execution Policy*).
   * **Solusi AUTO:** AUTO menyediakan opsi skrip **Windows Command Prompt (`.cmd`)** yang dapat dijalankan langsung dengan klik ganda (*double-click*) tanpa perlu konfigurasi ExecutionPolicy.

4. **Autentikasi Token GitHub Modern (PAT):**
   Sejak GitHub meniadakan login kata sandi langsung di Git CLI, pengembang harus menyematkan Personal Access Token (PAT) ke dalam remote URL. AUTO menyusun URL remote terotentikasi secara aman dan otomatis.

## ✨ FITUR-FITUR UTAMA & KAPABILITAS SISTEM

### A. Intelligent Readme Detector (Auto Change & Manual Change)
Fitur pendeteksi cerdas berkas `README.md` pada direktori proyek dengan 2 mode operasi:
* **Auto Change (Mode Default):**
  - Jika berkas `README.md` ditemukan di dalam direktori `public/`, skrip otomasi secara cerdas akan langsung memindahkannya ke direktori root repositori sebelum proses commit dan push.
  - Jika berkas `README.md` **tidak ditemukan** di dalam direktori `public/`, skrip otomasi akan langsung melanjutkan alur kerja Git berikutnya tanpa membuka atau membuat file kosong, sehingga proses deploy berjalan mulus tanpa interupsi.
* **Manual Change:**
  - Memberikan kontrol fleksibel bagi pengembang yang ingin menentukan path asal kustom, target pemindahan spesifik, opsi membuka berkas di text editor, atau memilih untuk melewati berkas jika kosong.

### B. Multi-OS Execution Payload Engine (.ps1, .cmd, .sh)
Menghasilkan skrip otomasi terstruktur rapi untuk 3 lingkungan sistem operasi utama:
1. **Windows PowerShell (`.ps1`)**: Lengkap dengan output teks warna, penanganan exception stream, serta pengecekan branch otomatis.
2. **Windows Command Prompt (`.cmd`)**: Format batch Windows standar yang dapat dieksekusi instan lewat klik ganda (*double-click*).
3. **macOS & Linux Bash (`.sh`)**: Skrip POSIX shell berstandar tinggi yang kompatibel dengan terminal Linux, macOS Zsh/Bash, dan WSL.

### C. Git Large File Storage (LFS) Auto-Tracker & Normalizer
* Menyediakan daftar cepat ekstensi binary umum: `.mp4`, `.zip`, `.psd`, `.exe`, `.tar.gz`, `.iso`, `.rar`, `.7z`, `.dll`, dll.
* Mengintegrasikan perintah `git lfs track`, normalisasi file `.gitattributes`, dan sinkronisasi `git lfs push --all origin <branch>`.
* Dilengkapi batas ukuran file opsional (*Size Limit Filter*).

### D. GitHub Release & Semantic Versioning System
* Integrasi pembuatan rilis GitHub secara otomatis.
* Menentukan tag versi semantik (`v1.0.0`, `v1.1.0`), judul rilis, deskripsi changelog markdown, serta flag draft maupun pre-release.

### E. Sinkronisasi Topik & Deskripsi Repositori
* Memperbarui deskripsi repositori GitHub dan topik tag (*repository topics*) langsung melalui skrip otomasi berbasis GitHub CLI (`gh`).

### F. Animasi Penulisan Kode Real-Time & Live Counter Footer
* Saat tombol **Generate Code** ditekan, kode di editor akan ditampilkan melalui animasi pengetikan halus dari atas ke bawah (*top-to-bottom typing animation*).
* **Live Counter di Footer:** Selama animasi berlangsung, baris teks di footer (indikator jumlah baris dan estimasi ukuran berkas) ikut beranimasi menghitung secara real-time dari 0 menuju angka total sebenarnya secara presisi.

### G. Cyber Terminal Simulator Interaktif
* Simulator terminal bergaya cyber futuristik dengan aksen neon cyan (`#00f3ff`).
* Menguji skenario eksekusi perintah Git sebelum dijalankan di komputer asli.
* Mensimulasikan pengecekan branch, commit push, status autentikasi, serta error handling (403 Authentication Error, 404 Repo Not Found, dan Non-Fast-Forward Conflicts).

### H. Dual Theme Engine (Light Mode & Dark Mode)
* **Dark Mode:** Tampilan cyberpunk deep-space dark bernuansa profesional, kontras tinggi, dan nyaman untuk mata pengembang saat malam hari.
* **Light Mode:** Tampilan bersih, elegan, dengan kontras tajam. Seluruh elemen—mulai dari seekbar, card solusi Vercel berlatar putih bersih, tombol interaktif, hingga empty state editor kode—disesuaikan sempurna tanpa distorsi warna.

### I. Pustaka Berkas Bersih & Kustomisasi Skrip Mandiri
* Pengembang dapat membuat berkas skrip kustom baru dari nol (*clean blank library*).
* Mendukung pengeditan nama berkas, pemilihan ekstensi, penambahan deskripsi kustom, ekspor individual, ekspor seluruh proyek ke arsip ZIP, serta penyimpanan permanen di LocalStorage browser.

### J. Progressive Web App (PWA) Offline-Ready
* Dilengkapi dengan Web App Manifest dan Service Worker offline-ready.
* Desain ikon card eksklusif (`pwa-card.svg`) berbasis logo cyan AlinLabs Indonesia.
* Dapat diinstal langsung ke desktop (Chrome, Edge) maupun smartphone (Android, iOS).

## 💡 PANDUAN SOLUSI MASALAH GIT LFS DI VERCEL (130-BYTE POINTER ERROR)

Jika aplikasi Anda yang menggunakan Git LFS mengalami error saat proses build di Vercel:
```bash
Error: File size too small (130 bytes pointer)
Error: Cannot read binary asset from Git LFS pointer
```

### Solusi Praktis:
1. Masuk ke dashboard proyek Anda di [Vercel](https://vercel.com).
2. Pilih repositori proyek yang bersangkutan.
3. Masuk ke menu **Settings** > **Environment Variables**.
4. Tambahkan variabel baru:
   * **Key:** `VERCEL_GIT_LFS_ENABLED`
   * **Value:** `1`
   * **Environment:** Pilih `Production`, `Preview`, dan `Development`.
5. Klik **Save**.
6. Masuk ke tab **Deployments**, klik tombol opsi (`...`) pada deployment terbaru, lalu pilih **Redeploy**.
7. Vercel akan mengunduh aset binary utuh melalui Git LFS dan build akan sukses 100%.

## 💻 PANDUAN MENJALANKAN & PENGEMBANGAN LOKAL (LOCAL DEVELOPMENT)

### Prasyarat Sistem:
* [Node.js](https://nodejs.org/) versi 18.x atau lebih baru.
* Pengelola paket [npm](https://www.npmjs.com/) atau [bun](https://bun.sh/).
* Peramban web modern (Google Chrome, Microsoft Edge, Mozilla Firefox, Safari).

### Langkah Instalasi:
```bash
# 1. Klon repositori proyek
git clone https://github.com/alvareza/auto.git
cd auto

# 2. Pasang seluruh dependensi aplikasi
npm install

# 3. Jalankan server pengembangan lokal (Port 3000)
npm run dev

# 4. Akses antarmuka di peramban web
http://localhost:3000
```

### Skrip Kompilasi & Produksi:
```bash
# Memeriksa validasi tipe TypeScript & sintaks
npm run lint

# Mengompilasi aplikasi untuk lingkungan produksi
npm run build

# Menjalankan server aplikasi produksi
npm start
```
